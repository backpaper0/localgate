# Implementation Plan

- [x] 1. LISTENポートスキャナの実装
- [x] 1.1 `/proc/net/tcp[6]` からLISTENポートを取得する機能を実装する
  - Linux カーネルが提供するTCP接続情報ファイルを読み取り、LISTEN状態（`st=0A`）のエントリを抽出する
  - `local_address` フィールドの16進数ポート番号をデコードし、TCPv4とTCPv6を両方対象にする
  - IPv4とIPv6で同一ポートが重複して現れる場合は1件に集約する
  - 取得結果を重複なしのポート番号リストとして返す
  - `/proc/net/tcp6` が存在しない環境（IPv6無効）では、エラーを記録しつつTCPv4の結果のみで継続する
  - _Requirements: 2.1_

- [x] 1.2 (P) ポートスキャナのユニットテストを実装する
  - テスト用の擬似ファイル内容（LISTEN・非LISTEN混在）を入力として、正しいポートリストが返ることを検証する
  - IPv4とIPv6の重複ポートが1件に集約されることを検証する
  - ファイルが存在しない・読み取れない場合にエラーが返ることを検証する
  - _Requirements: 2.1_

- [x] 2. 管理APIクライアントの実装
- [x] 2.1 (P) localgate管理APIと通信するHTTPクライアントを実装する
  - 疎通確認（GET /services）、サービス登録（POST /services）、サービス解除（DELETE /services/{name}）の3操作を実装する
  - 登録時のリクエストボディは `name` と `target` を含むJSON形式とする
  - 解除時に対象サービスが存在しない場合（404応答）はエラーとせず正常扱いとする（冪等性）
  - 登録時に競合（409応答）が発生した場合はエラーとして返す
  - 1と2のタスクはそれぞれ独立したコンポーネントを対象とするため並行実施可能
  - _Requirements: 1.2, 3.1, 4.1, 5.2_

- [x] 2.2 (P) 管理APIクライアントのユニットテストを実装する
  - `httptest.Server` でモックサーバを立て、各操作が正しいHTTPメソッド・エンドポイント・ボディでリクエストを送ることを検証する
  - 404応答時に `Deregister` がエラーを返さないことを検証する
  - 409応答時に `Register` がエラーを返すことを検証する
  - _Requirements: 1.2, 3.1, 4.1, 5.2_

- [x] 3. ポート監視コアロジックの実装
- [x] 3.1 Watcherの基本構造とサービス識別情報の準備を実装する
  - Watcherが保持する状態として「管理済みポートセット」と「前回スキャン結果」を定義する
  - 起動時にホスト名を取得し、先頭ラベル（最初の`.`より前の部分、`.`がなければホスト名全体）を抽出して保持する
  - サービス名を `{先頭ラベル}-{ポート番号}` 形式で、ターゲットを `{ホスト名}:{ポート番号}` 形式で生成するロジックを実装する
  - watchが管理するサービスの追跡対象は、このWatcher自身が登録に成功したポートのみとする
  - _Requirements: 3.4, 3.5, 4.4_

- [x] 3.2 ポーリングループと新規ポートの自動登録を実装する
  - 設定された間隔ごとにポートスキャンを実行し、前回結果との差分（新規に現れたポート）を検出する
  - 新規ポートが検出されたら管理APIにサービス登録リクエストを送り、成功したポートを管理済みセットに追加する
  - 登録成功時はサービス名とポート番号を標準出力にログとして出力する
  - スキャン失敗・登録失敗はいずれもエラーログを記録するのみとし、次のポーリングサイクルまで継続する
  - 監視中であることを示すログを適切なタイミングで標準出力に出力する
  - _Requirements: 1.5, 2.1, 2.4, 3.1, 3.2, 3.3_

- [x] 3.3 消滅ポートの自動解除を実装する
  - ポーリング差分で前回は存在したが今回消えたポートを検出する
  - 対象ポートに対してサービス解除リクエストを管理APIへ送り、成功したポートを管理済みセットから削除する
  - 解除成功時はサービス名とポート番号を標準出力にログとして出力する
  - 解除失敗はエラーログを記録するのみとし、管理済みセットに残したまま次サイクルで再試行する
  - Watcherが管理していないサービス（外部から登録されたもの）には一切干渉しない
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [x] 3.4 コマンド終了時の全サービスクリーンアップを実装する
  - コンテキストのキャンセルを検知したらポーリングループを停止し、クリーンアップシーケンスを開始する
  - 管理済みセットに含まれるすべてのポートに対して順次解除リクエストを送る
  - 一部のサービス解除が失敗しても残りの解除処理を継続する
  - 全件処理が完了したらクリーンアップ完了メッセージを出力してゼロ終了コードで return する
  - _Requirements: 5.2, 5.3, 5.4_

- [x] 3.5 Watcherコアロジックのユニットテストを実装する
  - ポートスキャナと管理APIクライアントをモックに差し替え、新規ポート検出時に Register が呼ばれることを検証する
  - 消滅ポート検出時に Deregister が呼ばれることを検証する
  - コンテキストキャンセル時に管理済みポートがすべて Deregister されることを検証する
  - 登録・解除失敗時に処理が継続し次サイクルで再試行されることを検証する
  - ホスト名ラベル抽出ロジックを様々なホスト名パターンで検証する（FQDN・単純名）
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3, 4.4, 5.2, 5.3, 5.4_

- [x] 4. watchサブコマンドの実装
- [x] 4.1 watchコマンドの定義とフラグを実装する
  - `localgate watch` サブコマンドを既存の cobra パターンに従って追加する
  - `--server` フラグ・`$LOCALGATE_SERVER` 環境変数・デフォルト値の優先順位でサーバURLを解決する共通ロジックを再利用する
  - `--interval` フラグで秒単位のポーリング間隔を指定できるようにし、デフォルトを1秒とする
  - 間隔に1秒未満の値が指定された場合はバリデーションエラーを返す
  - _Requirements: 1.1, 1.4, 2.2, 2.3_

- [x] 4.2 起動時のサーバ接続確認とエラー処理を実装する
  - コマンド実行時にlocalgate管理APIへの疎通確認を行う
  - 接続に失敗した場合はエラーメッセージを標準エラー出力に表示し、ゼロ以外の終了コードで終了する
  - 接続に成功した場合のみポート監視を開始する
  - _Requirements: 1.2, 1.3_

- [x] 4.3 シグナルハンドリングとWatcherの起動を実装する
  - SIGINT・SIGTERMを受け取ったらコンテキストをキャンセルしてWatcherの終了シーケンスを開始する
  - Watcherのクリーンアップ完了を待ってからコマンドを終了し、ゼロの終了コードで返る
  - SIGKILLのような強制終了を除き、通常のシグナルでは必ずクリーンアップが完了してから終了する
  - _Requirements: 5.1, 5.5_

- [x] 5. watch コマンド統合テストの実装
- [x] 5.1 watchコマンドのエンドツーエンドテストを実装する
  - `httptest.Server` で管理APIをモック化し、ポートスキャナをモックに差し替えた構成でテストを実行する
  - 新規ポート検出 → 自動登録 → 消滅 → 自動解除 の一連のサイクルが正しく動作することを検証する
  - コンテキストキャンセル時に全登録サービスが解除されることをエンドツーエンドで検証する
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 3.1, 4.1, 5.1, 5.2, 5.5_
